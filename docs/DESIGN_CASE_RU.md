# Game 1 — разбор учебного прототипа

## Цель прототипа

Проверить минимальную петлю погони в 2D: игрок управляет персонажем, видит направление и скорость движения, замечает пчелу и меняет маршрут, когда она приближается. Критерий успеха для этого этапа — **читаемая реакция на ввод и понятное преследование**, а не большой уровень или сложная боевая система.

## Дизайнерская схема

| Событие | Ожидаемое восприятие игрока | Состояние |
| --- | --- | --- |
| Нажатие направления | Персонаж сразу движется в нужную сторону | Скрипт движения есть; запуск сцены не проверен |
| Диагональное движение | Скорость не увеличивается неожиданно | Нормализация предусмотрена кодом |
| Остановка и смена направления | Анимация подтверждает действие | Параметры Animator передаются из кода |
| Приближение пчелы | Угроза заметна по траектории | Алгоритм преследования есть; компонент не подключён в опубликованной сцене |
| Контакт с пчелой | Игрок получает ясное последствие | Урон и задержка атаки ещё не реализованы |

Пока нет сцены, проверенной в Play Mode, эта таблица описывает проектное намерение и состояние файлов, а не результаты плейтеста.

## Почему такая структура

Сначала нужно добиться предсказуемого движения: без него нельзя оценивать сложность погони. Параметры Animator дают визуальную обратную связь на ввод. Пчела должна двигаться к позиции игрока, чтобы игрок видел связь между собственным маршрутом и поведением врага. Только после этого имеет смысл настраивать скорость пчелы, зону обнаружения, контактный урон и восстановление после ошибки.

## Критерии следующего играбельного среза

1. Основная сцена открывается без Missing Script и ошибок Zenject.
2. Персонаж ходит по WASD и стрелкам; по диагонали скорость не выше прямого движения.
3. Повороты и остановка корректно отражаются в анимации.
4. Пчела следует за игроком в сохранённой основной сцене.
5. Контакт с пчелой даёт одно предсказуемое последствие, а повторный урон ограничен задержкой.
6. Короткая запись показывает полный цикл: движение, обнаружение врага, уклонение и контакт.

Пункты 1–6 — **план проверки**, а не выполненные тесты. [Технический обзор сцены](PROJECT_REVIEW.md) описывает текущие препятствия.
